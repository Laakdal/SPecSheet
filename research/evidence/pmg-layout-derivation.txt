  cargo run --release -p specsheet-archive --example scs -- cat <path> > <file>

(the dumps stay outside the repository).

Command:
  python -I tools/research/model_layout.py <dumps>/*.pmd <dumps>/*.pmg

How the layout is pinned down (see the [ok]/[FAIL] lines below):
- Record sizes: each block's size is the gap to the next block's offset,
  divided by its count. Every block tiles exactly to the end of the file.
- PMG pools: (offset, size) pairs at 0x58..0x6c chain string pool -> vertex
  pool -> index pool -> end of file.
- Stream names come from the values, not the slot order: the "position" slot
  lies inside the piece AABB and inside the model sphere, the "normal" slot is
  unit length, the "tangent" slot has unit xyz and w = +-1. The uv slot's size
  is 8 x the piece's u32 at +12 (1, 2 and 3 sets seen).
- Quaternion order: 100+ identity locators store 1.0 in the FIRST float; the
  180-degree yaws (r_light, exhaust_m) store it in the third. So the order is
  (w, x, y, z), and the 180-degree turns are about y.
- Index streams: u16, index count x 2 bytes, each stream starting 4-byte
  aligned (2 bytes of padding after an odd count).

Corrections to what we had (both now in specsheet-formats):
- Piece header +60 is the vertex stride in bytes (36/52/60/68/28 seen), not a
  skeleton offset. The parser now rejects a stride that disagrees with the
  present streams; every truck model passes (real_install).
- Locators without a hookup point at an empty string (usually pool offset
  0); -1 was never seen. The parser now maps an empty string to "no hookup".
- Header 0x20..0x2f (and piece +20..+35) is a bounding sphere, centre and
  radius: every vertex lies inside it. The centre is not the AABB centre, and
  the radius is not half the AABB diagonal.

Archive-wide check of the stride rule: a throwaway example ran the Rust parser
(with the stride check) over every .pmg in base, base_vehicle, base_map,
base_share, core and def. 53,917 parsed and 0 failed, including 4,388 skinned
models (bone count > 0). So the stored stride also equals the sum of the
present streams when the bone index (4 x u8) and bone weight (4 x u8)
streams are present.

Not determined (always 0 in the six dumps; skinned models were checked only
through the stride rule above):
- PMD 0x0c; PMG 0x0c ("bones") and 0x10; the u64 at 0x18.
- PMD attribute header +8 (0 for every `visible` attribute).
- Piece +8: a u32 bit field (0xfffffff0, 0xfffff000, 0xf1fffff0, 0xf2fff110,
  0xffffffff seen). It tracks the uv set count; its meaning is Unknown.
- Position of the colour2 and bone streams (never present here).
