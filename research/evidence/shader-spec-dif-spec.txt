Shader spec sources: eut2.dif.spec family (docs/app/shader-specs/dif-spec.md), ETS2 1.60.1.7
=====================================================================================

Clean-room note (D13): the game's shaders were read only to learn the maths. All extracted
text was kept outside the repository, in the session scratchpad (specwriter-dumps/). This
file lists what was read. It contains no shader text.

Commands (Git Bash)
  export ETS2_DIR="D:/Steam Library/steamapps/common/Euro Truck Simulator 2" MSYS_NO_PATHCONV=1
  export CARGO_TARGET_DIR=<scratchpad>/target-specwriter
  cargo build --release -j 2 -p specsheet-archive --example scs
      (the older prebuilt scs.exe could not open .rfx: metadata record 0x07)
  scs ls effect/eut2 ; scs ls effect/eut2/<dir>                  list effects
  scs cat effect/eut2/<dir>/<effect>.rfx                          effect -> passes -> shader objects
  scs cat effect/eut2/_shd/<hash>.glsl.vso|fso                    shader object (container "SHDO")
  scs cat effect/deferred/rs/<name>.rs                            render states
  scs cat effect/deferred/<dir>/<effect>.rfx, effect/deferred/_shd/<hash>.glsl.fso
  scs cat effect/def/{flavors,inputs,uniforms,vas}.sui, effect/def/eut2_interfaces.sui
  Then, in the scratchpad: extract printable runs from each object, keep the GLSL 330 part,
  and diff variants against each other to see what each flavor adds.

Mapping effect name -> shaders
  The .mat effect name is the .rfx file name, in the directory named after the base with the
  dots replaced by underscores. Examples: eut2.dif.spec.weight.add.env.tsnmapuv is in
  effect/eut2/dif_spec_weight_add_env/; eut2.dif.spec.tsnmap is in effect/eut2/dif_spec/.
  'nofresnel' and 'oclu' are part of base names: dif_spec_add_env_nofresnel, dif_spec_oclu,
  dif_spec_oclu_add_env, dif_spec_oclu_weight_add_env.
  In each .rfx only the techniques with "path: glsl" were used. Normal-mapped effects have two
  glsl techniques: one with "condition: nmap" (normal-mapped shaders) and one without, which
  reuses the non-normal-mapped shaders.

How each fact was established
  - Per-flavor differences: the normalised fragment bodies were diffed pairwise:
    base vs weight; base vs add.env; add.env vs nofresnel; add.env vs weight.add.env;
    base vs tsnmap; tsnmap vs tsnmapuv; base vs a; base vs oclu; weight.add.env.tsnmapuv vs
    tsnmapuv2. The defattr (G-buffer) bodies were diffed for base vs weight and base vs add.env.
  - The forward and deferred paths agree: the deferred compose pass combines the G-buffer and
    the light buffers with the same equation as the forward pass.
  - The specular-gate switch: the 'weight' G-buffer pass sets a flag that the sun-light pass
    reads to choose N.L over sat(10 N.L).
  - UV streams: vertex objects of the base, tsnmap, tsnmapuv, tsnmapuv2, weight.add.env and
    oclu variants, plus the effect interface table (vertex streams per effect) and the
    vertex-stream table (UV-slot names and exporter defaults).
  - .mat names and defaults: the material-input table (names, UI labels, defaults; "fresnel" is
    labelled "(bias, scale)", default (0.2, 0.9)) and the material-uniform table (which inputs
    feed which engine constant). .mat attribute names cross-checked in
    research/evidence/material-survey.txt; texture_oclu confirmed in /automat/12/1276d7b45261b635.mat.
  - The material-uniform table lists no .mat input for the reflection rotation, the global
    reflection scalar or the specular-mask remap, so they are engine-supplied.
