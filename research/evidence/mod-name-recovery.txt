Recovering file names in HashFS v1 mod packages (docs/formats/mods.md)
=======================================================================

Subject: the 21 HashFS v1 packages in the test install's mod folder and the
mounted game (ETS2 1.60.1.7), read only. Package names are public mod
names; no profile data.

Commands (read-only):
  cargo run --release -p specsheet-data --example mod_names -- [--list] [--zips "<home>/mod"] <v1 packages>
  one-off examples (deleted after use) for the convention counts in 3.
  python -I <scratch>/stems.py "<home>/mod"   (stdlib zipfile, ZIP mods)


1. Why names go missing
-----------------------
A v1 entry record holds only a CityHash64 of its path (hashfs-v1-derivation.txt).
Names exist only in directory listings, and listings are optional:
- no package has a root listing (known before, 20 of 20);
- NG Sound.scs (91 entries, not in the earlier survey) has no directory
  entry at all: every record has flags bit 0 clear.
The game needs no names, since it looks files up by full path; a tool that
lists a package's contents has only hashes. A name can be recovered only by
hashing a candidate path and finding it in the index.


2. Candidate sources (specsheet_data::mod_names, specsheet_formats::paths)
--------------------------------------------------------------------------
- every path of the mounted game: walk from the root listing, 626,878
  paths (606,713 files, 20,165 directories), about 2 s;
- parents of every candidate, and the listings of directory entries found;
- absolute paths mentioned in any entry's bytes, named or not ("/..."
  after a quote, '|', '=', ':', '(' or space; "#event" cut), relative
  @include targets, and relative .tobj names inside .mat files;
- manifest icon and description_file;
- the conventions counted in 3.
Every candidate counts only when its hash is in the package, so a wrong
guess can only miss, never mis-name.

5. NG Sound.scs in detail
-------------------------
Manifest: compatible_versions[] "1.59.*" (the game is 1.60.1.7).
Named 71 of 91 with game paths (80 with the other packages too):
  sound/truck: 2 FMOD banks (RIFF FEV, 182 MB) + 2 .bank.guids
  def/vehicle/truck/scan.ng.common/..., ng.dc16.122.common/engine:
    36 .soundref, new paths
  def/vehicle/truck/scania.{s,r}_2016/{cabin,chassis,engine,interior,
    transmission}/sound*.sui: 18 files that replace game files
  def/vehicle/truck/scania.{s,r}_2016/accessory/badge/530{s,r}_scs.sii
    (addon-unit convention), their badge models (.pmd/.pmg)
  material/ui/accessory/max2712.{dds,tobj,mat} (icon of the author; no
    unit in the package names it)
  manifest.sii, description.txt, icon .jpg
Unnamed 20 with game paths only (11 with the other packages):
  19 sound fragments ("# Configuration of the ... sounds", the form of the
     game's sound*.sui includes) that match no 1.60 path and no reference.
     Hypothesis: they replaced 1.59 files that 1.60 renamed or dropped, so
     they no longer apply.
   1 .soundref: source="/sound/truck/ng_effects_paid.bank#interior/blinker_off".
     Its name follows its siblings (def/vehicle/truck/scan.ng.common/
     interior/blinker_off.soundref hashes to it), but sibling guessing is
     not in the library.
.soundref (37 in the package): text lines key=value; "source" in all 37
(bank path, '#', event path), "position_offset" (x;y;z) in 8. The game
has .soundref files too (e.g. engine/sound_590s_engine.soundref); whether
they use the same keys is not checked (Unknown).
Hypothesis: the game finds accessory files by directory listings, so the
two badge units, which no listing names, may never appear in the game.


6. Search limits (after a security review)
------------------------------------------
Hostile content could grow the search without end: the candidate cap counted
only paths already tried, not those waiting, listing names skipped the path
checks, and the bytes scanned per package had no bound. Every queued path now
passes specsheet_formats::paths::clean (at most 512 bytes; no empty, "." or
".." part), each is queued once, and three limits hold per package. Measured
on the test install (one-off examples, deleted after use):
  limit                               set to     largest real need
  paths ever queued                   4,000,000  ~1,270,000 (626,878 game +
                                                  642,535 ZIP names and refs)
  total length of those paths         256 MiB    ~59 MB (34.8 + 24.4)
  bytes read to scan, per package     4 GiB      at most 2.37 GB: 1.18 GB of
                                                  files <= 1 MiB (promods-eu-
                                                  model1), each read at most
                                                  twice (unnamed, then named)
  one file or listing scanned         1 MiB      largest listing 87,488 B
Results with the limits, same 21 packages: 139,693 named from the packages
alone, 164,645 with game paths and 167,421 with --zips too, all unchanged
from section 4.


7. skybox.scs, and companions of missing files
----------------------------------------------
A sky texture package (329 entries, salt 0, 4.5 GB, not in the earlier
survey). Like NG Sound it has no directory entry at all, so every name comes
from paths inside its own files. Manifest, description and icon are named;
the only .sii is manifest.sii.
Before the change below: 197 named from the package alone, 205 with game
paths, 124 unnamed. The other mod packages as candidates (--zips) add none.
The 124 unnamed, by content (one-off example, deleted after use):
  29  .tobj descriptors pointing at model/skybox/nskies/.../jbx_sky*.dds
      files that are not in the package. Each one's own path is that
      texture path with .tobj (29 of 29 hash-verified).
  70  3-byte files, all "# @". Unknown.
   7  hex text: 4 x 64 chars (32 bytes) and 3 x 460,010 chars (230,000
      bytes), no known magic once decoded. Unknown.
   3  readme text (2 English, 1 Spanish).
  15  Windows Internet Shortcut files ("[InternetShortcut]", URL=...).
Hypothesis: the 29 descriptors are leftovers whose textures were removed;
nothing in the package names them.
Change: companions are now tried for every candidate, found or not, so a
missing texture still yields its .tobj. Results with game paths:
  skybox.scs                 226 from the package alone, 234 with game paths, 95 unnamed
  the other 21 packages      139,695 alone, 164,647 with game paths (+2 each, none lost)
With --zips too: 167,657 of 171,094 entries in all 22 packages (the 21:
167,423, +2 in Add-On MAN TG3, now 3,217 unnamed; skybox 234, unchanged).
The 8 game paths it replaces are dlc/{dead_end,direction_blocker,
invisible}_dlc.{pmd,pmg,tobj} (invisible_dlc has no .tobj).
No .sii in the package names the sky textures, and no game path or other
mod in the folder does either. Hypothesis: the package needs a separate
definitions mod (its Spanish readme lists "Compatible: ... JBX Settings
RC") to change the sky.
Packing order (entries sorted by data offset; one-off example, deleted):
the packer wrote files folder by folder, names sorted within a folder, so
an unnamed entry's named neighbours show its folder and where its name
sorts. Not a name, but it narrows a guess, which the hash then checks.
- The two named model/skybox/{sun,skycloud}/none.dds are 3 bytes, "# @",
  the same as the 70 unnamed tiny files: placeholder textures (Confirmed
  by content). None of the 70 is at a 1.60 game path.
- The 8 replaced dlc/ files are each 64 bytes of the same hex text as the
  4 unnamed 64-char files. Two of those, sorted just before their .pmd,
  are dlc/dead_end_dlc.dds and dlc/direction_blocker_dlc.dds
  (hash-verified; no rule names them yet).
- The 15 Internet Shortcuts each sit first in a texture folder, so each
  credit folder (environment-textures, hdrmaps, hdri-skies-360, ...) holds
  one, sorted before the jbx_* files (an upper-case name: Hypothesis).


8. Comparison with Extractor, and facts for new rules
-----------------------------------------------------
Extractor (sk-zk, GPL-2.0) release 2026-07-29, win-x64 zip, SHA-256
d493dc7d1834854effe12b80f6598cd1a8d5e754b069d7321f8802f72d64b2f7 (as
published by GitHub), run with --deep --list --dry-run -q on each of the 22
v1 packages; nothing extracted. Only its printed paths are used, each
checked against the package by hash. Its --list prints files only, so the
counts below are files (directory entries excluded on our side).
  files named                 ours (game + ZIP candidates)  160,589
                              Extractor                     160,726
                              both                          158,616
                              only ours                       1,973 (MAN TG3 1,926, NG Sound 47)
                              only Extractor                  2,110 (MAN TG3 2,108, skybox 2)
In 17 of 22 packages both name exactly the same files. Extractor's 2,110:
  695  /automat/<xx>/<hash>.mat materials (MAN TG3)
 1409  .dds textures whose paths use ? * < > : # (MAN TG3), named inside
       .tobj files; our scanner keeps only [A-Za-z0-9_-./] and drops them
    6  .pmd/.pmg (skybox dlc/direction_blocker_curve.{pmd,pmg}, 4 in MAN TG3),
       not paths of the 1.60 install (probably from Extractor's own list)
Facts checked on our own data before use:
- automat: every one of the game's 65,473 automat/<xx>/<name>.mat files is
  named by the CityHash64 of its content, as 16 lower-case hex digits, in
  a folder of the first two (65,473 of 65,473; one-off example).
- standalone .tobj (24,981 in the mod folder's v1 and ZIP packages): magic
  01 0a b1 70; from 0x28, records of u64 length + path bytes run to the end
  of the file in 24,979: one record in 24,970, six in 9 (cube maps); 2 have
  an invalid length. Paths start with '/'.
- map sectors: the game's map/europe has 1,101 sectors named
  sec<x:+0000><z:+0000> (x -24..19, z -31..21) with .base .aux .data .desc
  (.snd 1,100). Every v1 package here is named as completely by us as by
  Extractor, so sector guessing names nothing here: not implemented (not
  observed).
- unreadable entries: 0 in all 22 v1 and all ZIP packages; Extractor printed
  no decoys. Junk and decoy handling: not observed, not implemented.
- 3nK: 2 entries, both in MAN TG3 ("3nK" 01 00 ...). XOR against the
  expected "SiiNunit" start gives no repeating key, and the MIT reference
  (sii-decode-rs) has no 3nK. Unknown; needs the exe (REA).
- encrypted (ScsC) or binary (BSII) SII: 0 in mods.


9. New rules: results, and content types
----------------------------------------
Rules added from section 8 (each test-first): .tobj texture paths read as
length records; automat/<xx>/<hash>.mat from each unnamed entry's content;
packing-order neighbours (section 7) with the package's own extensions;
v1 packages as candidates for each other (example flag --others, which
replaces --zips and also scans the v1 packages of the folder).
22 v1 packages, mod_names --others "<home>/mod":
  named from the packages alone   142,029 (was 139,921)
  named with all candidates       169,777 of 171,094 (was 167,657)
  Add-On MAN TG3                    6,445 of 7,558 (was 4,341): +695
                                    automat, +1,409 .dds from .tobj records
  skybox                              250 (was 234): +2 dlc/*.dds by packing
                                    order, +14 files in model/skybox named
                                    by paths in another v1 package
  every other package             unchanged
Content types of unnamed entries (specsheet_formats::sniff) use signatures
seen on the named files of the folder's ZIP packages (one-off example that
printed the four most common first-8-byte heads per extension):
  "DDS "                 .dds: one head, 3,314 of 3,314
  01 0a b1 70            .tobj: one head, 3,275 of 3,275
  15 67 6d 50 ("\x15gmP") .pmg: all four top heads (770 of 1,509)
  ff d8 ff               .jpg: all four top heads (20 of 32)
  89 "PNG" 0d 0a 1a 0a   .png: one head, 9 of 9
  "SiiNunit" (BOM ok)    .sii: 63,638 of 63,659 in the top heads (others:
                         unit text without the header, e.g. "accessory")
  "material" / "effect"  .mat: 4,366 of 4,883, and 517 more after a
                         newline (leading whitespace is skipped)
  "source="              .soundref: 2, and 141 after a BOM (skipped)
  "RIFF", "FEV " at 8    .bank: RIFF in all four top heads of 25; FEV seen
                         at offset 8 in NG Sound's 2 banks
.pmd/.pma/.pmc start with a small u32 version (4/5/6) only; too weak to
label, so those stay .bin. A label never names a file.
