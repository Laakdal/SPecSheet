Standalone (loose) .tobj headers in mod packages, and their .dds (D20)
=====================================================================

Subject: every loose .tobj in the 58 packages of the test install's mod folder
(ZIP and HashFS v1; v1 names recovered from the package alone), ETS2 1.60.1.7.
Packages are only read; output is counts only. Game packed textures are read
through the mounted install (base and DLC).

Command (2026-11-07):
  cargo run --release -q -p specsheet-research --example tobj_survey -- "<home>/mod"

The layout of the path records from 0x28 is in mod-name-recovery.txt section 8
(magic 01 0a b1 70; u64 length + path, filling the file; six for a cube).


1. Which header bytes vary
--------------------------
24,125 loose .tobj. Over 0x04..0x27, bytes with more than one value (count of
files per value):
  0x14: 0 x5174, 1 x18951
  0x16: 0 x23613, 1 x26, 2 x485
  0x18: 2 x24109, 5 x16
  0x1a, 0x1b: 1 x2425, 3 x21700 (always equal to each other)
  0x1c: 0 x367, 1 x2388, 2 x4857, 3 x16513
  0x1e: 0 x10371, 2 x13750, 3 x1, 4 x2
  0x1f: 0 x10369, 2 x13752, 3 x1, 4 x2
  0x20: 0 x24113, 2 x10, 3 x1
  0x21: 0 x18197, 1 x5927
  0x25: 1 x24088, 0 x6, 136 x25, 204 x6
  0x26: 0 x23364, 1 x645, 57 x110, 204 x6
  One file holds 32 (a space) in 0x05..0x27 and is not a valid header; 0x04 is
  1 in one other file. Every other byte of 0x04..0x27 is 0 in all files.


2. The bytes against the game's packed texture at the same path
---------------------------------------------------------------
2,775 loose .tobj override a path the game packs. The game's records for that
path (ImageMeta / SampleMeta, docs/formats/textures.md) beside the loose bytes:
  0x18=2: every one is a 2D texture; 0x18=5: the one cube map (cube 1).
  0x1e=0: game address u Repeat in 1,243 of 1,342; 0x1e=2: ClampToEdge in
          1,420 of 1,433.
  0x1f=0: game address v Repeat in 1,248 of 1,343; 0x1f=2: ClampToEdge in
          1,419 of 1,433.
  0x20=2 only on the cube map (address w; 0 elsewhere).
  0x1c=2: the game packs no mipmaps in 1,121 of 1,123; 0x1c=1 and 3: with
          mipmaps in 1,645 of 1,652.
  0x1a/0x1b (1 or 3): no relation to the game's filters, which are linear in
          all 2,775.
Mods may change a texture's sampler on purpose, which explains the minority.

Colour space. DX10 .dds headers name their own DXGI format, sRGB or not. For
the 2,483 pairs whose .dds is a legacy FourCC or uncompressed (no colour space
in the file), the game's packed format against the loose bytes:
  0x26=1: game linear (not sRGB) in 64 of 64
  0x26=0: game sRGB in 2,409 of 2,419
  0x16=1: game linear in 19 of 19
  every other byte: no split.


3. The .dds files
-----------------
Formats of the .dds the first path names (24,125):
  DX10 header, by DXGI: 29 x42, 61 x2, 71 x4, 72 x976, 75 x4, 78 x2556,
    83 x355, 87 x1, 88 x16, 91 x595, 93 x2, 98 x221, 99 x106
  legacy FourCC: DXT1 x1185, DXT3 x7, DXT5 x13660, ATI1 x7, ATI2 x309,
    0x74 (A32B32G32R32F) x17, four spaces x1
  uncompressed (no FourCC): 32-bit x3476, 24-bit x132, 8-bit x66
  missing (the named .dds is not in the package) x383, too short x2
BC7 (DXGI 98/99) is not among the formats the game's packed textures use
(specsheet-archive pixel_layout covers every observed one), so it is new with
mods.


Reading
-------
- Hypothesis (strong): 0x18 is the texture type, 2 = 2D and 5 = cube.
- Hypothesis (strong): 0x1e, 0x1f and 0x20 are the address modes for u, v and
  w, in the code space of the packed sample record (0 Repeat, 2 ClampToEdge;
  docs/formats/textures.md).
- Hypothesis (strong): 0x1c = 2 means no mipmaps; 1 and 3 have them.
- Hypothesis (strong): 0x26 = 1 (and 0x16 = 1) marks a linear texture; the
  game reads every other loose texture without a DX10 format as sRGB.
- Unknown: 0x14, 0x1a/0x1b, 0x21, 0x25. The loader does not use them.
