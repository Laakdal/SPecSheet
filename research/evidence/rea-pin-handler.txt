Observed structure
------------------
- It switches on the event type (cases 1-8, 0xb, 0xc, 0x10) and on widget ids.
  The ids it tests exist in the tuning screen's layout files:
  402 = filter.button.id and 403 = clear.input.button
  (ui/truck_configuration_left.sii), 7500 = help.icon (..._right.sii). It also
  tests 300, 401, 460-462, 0x1d4c (7500).
- Input actions are compared as tokens (decoded from the constants):
  selectfcs, select, selectalt, back, joy_sec_prv / joy_sec_nxt,
  joy_nav_prv / joy_nav_nxt, j_trzoom_in / j_trzoom_out, j_tr_att_tra,
  shortcut_1, shortcut_2h, shortcut_3h.
- Pin navigation: the handler keeps the focused pin's index on the screen
  object. The pin button is 10000 + that index, or 11000 + index for a
  hookup. A widget counts as a pin when its id - 10000 < 10000, i.e. pins use
  ids 10000-19999.

Conclusions
-----------
Observed:
  - FUN_140fbf860 is the tuning screen's input handler (truck_config_hdl_u):
    buttons, gamepad and keyboard actions, focus. It does not create or place
    pins.
  - Gamepad: joy_sec_prv/nxt step between sections (tabs, Hypothesis from the
    names), joy_nav_prv/nxt step between pins, j_trzoom_in/out zoom the truck
    view.
  - Pin ids form the range 10000-19999 (accessory pins from 10000, hookup
    pins from 11000).
Unknown:
