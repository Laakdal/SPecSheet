PMG piece +8: UV slot routing
=============================

Commands (Git Bash, ETS2 1.60.1.7, from the repository root):

  export ETS2_DIR="D:\Steam Library\steamapps\common\Euro Truck Simulator 2" MSYS_NO_PATHCONV=1
  # Run A: every truck model (default root vehicle/truck)
  cargo run --release -p specsheet-research --example uv_routing_survey
  # Run B: wider roots
  cargo run --release -p specsheet-research --example uv_routing_survey -- vehicle model model2 prefab prefab2
  # Run C: per piece, the Gigaspace cabs (cabin_a, cabin_8x4 are the two
  # accessory_cabin_data units named @@cabin_gigaspace@@) and two DAF doors
  cargo run --release -p specsheet-research --example uv_routing_survey --     /vehicle/truck/mercedes_actros_2014/cabin_a.pmd /vehicle/truck/mercedes_actros_2014/cabin_8x4.pmd     /vehicle/truck/daf_2021/accessory/cab_door/std_xf.pmd /vehicle/truck/daf_2021/accessory/cab_door/win_xf_uk.pmd

The tool reads the stored u32 at piece +8 (`Piece::uv_routing`), splits it
into 8 nibbles (slot 0 = least significant) and checks each rule per piece.
Effects are read from the piece's material in every look of the .pmd (only
the .mat effect name; no shader was opened). Excerpts below; full output is
regenerated by the commands.

Verdicts
--------
C1 Confirmed. Nibble n holds a stored UV set index (0..3) or 0xf. Slots 3, 4,
   5 and 7 are 0xf in every piece; only slots 0, 1, 2 and 6 are ever used.
   No nibble names a set at or beyond the piece's UV set count.
   Run A 36,893 of 36,893 pieces; run B 611,638 of 611,638.
C2 Confirmed. The UV set count equals 1 + the highest routed set (0 when all
   nibbles are 0xf), and every stored set is routed to at least one slot.
   Run A 36,893 of 36,893; run B 611,638 of 611,638. So the field fully
   explains the stored set count: no unrouted (spare) set exists.
C3 Confirmed. Slot 0 is used (always set 0) exactly when the piece stores UV
   sets; pieces with no UVs store 0xffffffff. A 36,893/36,893, B 611,638/611,638.
C4 Confirmed. Slot 6 is used exactly when some look's effect has a `tsnmapuv`
   or `tsnmapuv2` token. A 36,893/36,893; B 611,638/611,638. (Plain count for
   the spec author: 33 truck pieces with `tsnmapuv2` carry slot 6, 6:0 x2 and
   6:1 x31.)
C5 Confirmed for truck models only. Slot 1 is used exactly when a look has
   `oclu`, `mult`, family `lamp` or family `truckpaint`; slot 2 exactly when a
   look is `truckpaint`. A 36,893/36,893. Outside vehicle/truck other effects
   also route slots 1 and 2 (run B fails 93,140 / 61,520: `amod` 63,577
   pieces, `window.day`, `leaves`, `dif.spec.weight.weight...` terrain-style
   effects, ...), so slots 1-2 are generic extra coordinates whose consumer
   depends on the effect.
C6 Confirmed. A routed set other than 0 is never a byte copy of set 0
   (run A: slot 1 set 1: 0 of 3,212; slot 6 sets 1/2/3: 0 of 5,766/1,003/94).
C7 Confirmed. No .mat used by a truck model has a per-texture attribute that
   names a UV set: the only per-texture keys over 4,822 materials are
   sampler, u/v/w_address, mip/min/mag_filter and aniso. Run B: the same
   key set (no others) over 59,516 materials.
H1 Hypothesis. Nibble n is the stored UV set that feeds the shader's UV
   slot n (texcoord n). C1-C6 reproduce every one of 611,638 pieces, but
   the engine's reading of the field is not observed (next step: REA on
   eurotrucks2.exe for the code that reads piece +8 while building vertex
   declarations, or a game screenshot of a piece whose slot-6 set differs
   from the set the current code uses).
H2 Hypothesis. Slot 6 is the `tsnmapuv` normal map's coordinate ("UV
   Normal" in the dif.spec spec); it rests on C4 plus the spec's slot
   number. Its set is per piece, not fixed: truck pieces 6:0 1,316,
   6:1 5,766, 6:2 1,003, 6:3 94 (run B 127,473 / 16,893 / 13,174 / 289).
H3 Hypothesis. For `oclu` the occlusion coordinate is slot 1; truck
   pieces route it from set 0 (801 pieces of all slot-1 users) or set 1
   (3,212); `oclu` pieces alone: 1:0 x6, 1:1 x782 (flavour table below; a
   piece whose looks differ counts once per distinct flavour).
H4 Hypothesis. truckpaint reads the paint mask through slot 1 and the
   alternate (altuv) mask through slot 2. Every truckpaint piece routes
   both, also when its .mat has no `altuv`, which fits altuv being chosen
   by the paint job at run time (REVERSE_ENGINEERING.md, paint effects).
   It agrees with the peer screen test (REVERSE_ENGINEERING.md "UV sets":
   Actros 2014 Gigaspace with an alternate_uvset job, only set 2 puts the
   livery on the door): run C, both Gigaspace cabs' paint pieces
   (cabin_a.pmd piece 5, cabin_8x4.pmd piece 3, truckpaint.tsnmapuv.altuv,
   3 sets) store 0xf0fff210, slot 2 = set 2. That case does not tell the
   routing from the current rule apart (both give set 2).
C8 Confirmed (measurement). `specsheet_data::render::paint_uv_set` against
   slots 1/2 of truckpaint pieces: run A 1,725 pieces, mask agrees 1,658,
   alt agrees 974; run B 4,986, mask 4,776 (96%), alt 2,423 (49%).
   Largest disagreements:
   - 0xf2fff110 (3 sets, 1:1 2:1 6:2; 535 truck pieces, 2,153 in run B):
     the rule sends altuv to set 2, the piece's slot-6 (normal-map) set;
     the routing says set 1.
   - 0xf1fff000 (2 sets, 1:0 2:0 6:1; 62 truck pieces, 144 in run B): the
     rule takes the mask from set 1, the slot-6 set; routing says set 0.
C9 Confirmed (content, run C). In both DAF door examples the set the rule
   picks there is collapsed to one corner of the texture, while the
   routed set spans a region:
   - std_xf.pmd piece 0 (0xf1fff000): set 0 u 0.220..0.779 v 0.535..0.792;
     set 1 (slot 6) u 0.009..0.011 v 0.993..0.996.
   - win_xf_uk.pmd piece 0 (0xf2fff110): sets 0 and 1 u 0.220..0.779
     v 0.535..0.792; set 2 (slot 6) u 0.009..0.011 v 0.993..0.996.
H5 Hypothesis (rests on H4). The current rule samples the paint mask
   from the normal-map coordinate on the C8 disagreement classes (2,153 +
   144 + smaller classes in run B), so on those pieces a livery would
   collapse to one texel region. Next step to confirm: a screen test with
   an alternate_uvset paint job on a 0xf2fff110 piece (e.g. DAF 2021
   XF door, win_xf_uk) comparing set 1 (routing) with set 2 (rule).
