effect.scs shader survey (ETS2 1.60.1.7)
=========================================

Commands (Git Bash, ETS2_DIR="D:/Steam Library/steamapps/common/Euro Truck Simulator 2", MSYS_NO_PATHCONV=1,
research examples built with: cargo build --release -p specsheet-archive --example scs --example survey):

  survey "$ETS2_DIR/effect.scs"
  scs ls effect ; scs ls effect/eut2 ; scs ls effect/eut2/truckpaint ; scs ls effect/eut2/_shd
  scs ls effect/eut2/_shd | sed -E 's/^[0-9a-f]+\.//' | sort | uniq -c
  scs cat effect/eut2/_shd/<hash>.glsl.fso      (then: extract printable runs / find "void main")
  grep -a -l "_flake_light" <all extracted eut2 *.glsl.fso>

Extracted shader text was kept OUTSIDE the repo (session scratchpad). Never commit it: it is game code.


1. effect.scs holds the game's compiled shaders  [Confirmed]
   survey: 15511 entries, all reachable; 8970 listed-but-missing (skipped).
     .fso (fragment shader objects): 10433, zlib
     .vso (vertex shader objects):   4854, zlib
     .rs:  111  (render-state snippets, e.g. effect/generic/dry_tex/zeq_add.rs)
     .sui: 3    (effect interface tables, "generated by deployfx")
   Top-level: effect/{def,deferred,eut,eut2,generic}; per-effect directories under eut2/ match
   material effect names (dif, dif_spec_add_env, glass, lamp, light, truckpaint, ...).

2. One shader per graphics API, keyed by hash + API suffix  [Confirmed]
   effect/eut2/_shd: 10398 files named <md5-like hash>.<api>.<stage>:
     glsl.fso 1070  glsl.vso 1488   (OpenGL GLSL)
     spv.fso   991  spv.vso   768   (Vulkan SPIR-V)
     sm4x.fso  951  sm4x.vso  492   (D3D shader model 4)
     sm5x.fso  951  sm5x.vso  492   (D3D shader model 5)
     sm51.fso  953  sm51.vso  494   (D3D12 SM5.1)
     sm60.fso  989  sm60.vso  759   (D3D12 SM6.0 / DXIL)
   Every object starts with the container magic "SHDO", u32 version 7, then a header/table
   (layout not decoded yet).

3. The GLSL variants contain readable GLSL 330 source  [Confirmed]
   Sample 0011310899832d5c279d1319851771dc.glsl.fso (34,933 bytes) holds plain text starting
   "#version 330 / #extension GL_ARB_separate_shader_objects", with named structs:
   lighting_factors_t, deferred_parameters_t (fog, tonemap_params, bloom_params, eye_adapt,
   envmap_matrix, color_correction), vertex_in_tmp_t (position, color, 4 texcoords,
   packed_tangents, normal), samplers tex2d/texcube/buffer.
   Variable names are generated (cg_TexCoordN, _TMPnnn) but uniform and texture names survive.

4. Truck paint math is readable  [Confirmed]
   147 of 1070 eut2 GLSL fragment shaders reference paint/flake identifiers:
   _flake_setup, _paintjob_base_color, _texture_paintjob, _texture_flakenoise, _flake_light,
   _flake_color, _flip_color, _paintjob_{r,g,b}_color.
   main() of 0bd28c17bd2941d44ffddaef462f77b4.glsl.fso shows:
     - normal from _texture_nmap (xy * 2.00787 - 1.00787, z reconstructed), tangent-space basis
     - flip paint: facing = saturate(N.V); colour = lerp(facing, facing^2, flip_color.w) * paintjob_base_color
                   + lerp(1-facing, (1-facing)^2, flip_color.w) * flip_color.rgb
     - paint job texture blended over it by its alpha (_texture_paintjob, second UV set)
     - albedo = texture_base.rgb * paint colour * material_diffuse
     - flakes: _texture_flakenoise sampled at uv * (flake_setup.x, flake_setup.x*flake_setup.w),
       coverage = 1 - flake_color.w * noise.a, own light _flake_light, specular exp(flake_setup.z * N.H)

5. Effect -> shader mapping lives in .rfx files the reader cannot open yet  [Hypothesis, strong]
   Per-effect files such as effect/eut2/truckpaint/eut2.truckpaint.airbrush.rfx are listed in
   directory listings but every one tried returns NotFound. The 8970 skipped entries all carry
   metadata record type 0x07 ("unsupported metadata record type 0x07"), and their count equals
   the listed-but-missing count. The .rfx files presumably map an effect name plus flavours
   (airbrush, flipflake, altuv, a, skinned, ...) to the _shd hashes.
   Next step: decode metadata record 0x07 in specsheet-archive (see ASSET_FORMATS "Metadata records"),
   then read one .rfx.

Implementation implications
   - 1:1 material look is reachable. Port the math from the GLSL into our own WGSL Bevy
     materials, starting with truckpaint (flip + paint job + flakes), dif_spec_add_env
     (env reflections), glass and lamp.
   - Alternative, unproven: load the user's own SPIR-V at runtime (wgpu/naga accept SPIR-V).
     This depends on reproducing the engine's uniform/sampler bindings exactly. Treat it as research.
   - Rights: these shaders are game code. Reading them to learn the math is the same as the
     rest of this RE work. Copying their source into the repo is redistribution: write our
     own WGSL, and keep any extracted text in gitignored research/extracted/ or outside the repo.
