Observed control flow
---------------------
1. The accessory record holds a 64-bit word at +0x40: the low 16 bits are a
   kind code, the bits above it a "cart" index. The routine finds the cart
   record with that index in an array of 0x198-byte records, or logs
   "Cart data not found".
2. It derives a token from the accessory and compares it with a 12-entry token
   table at 0x14350cc00 (.data, zero in the file, filled at run time). On a
   match the button id comes from the u32 table at 0x141d39978 and that button
   is activated: the accessory has a fixed button, not a pin.
3. Otherwise it picks a group button: table 0x141d39990 indexed by one flag.
   The flag is set when the slot token is in a token list reached through the
   screen (offset +0x138, then +0x3c8 / +0x3d0 count) or equals the token at
   0x142c02ff0. The group button is searched for by id and activated.
4. It then searches the acc_info_t array (64-byte records) for the record whose
   first field equals the cart's index and whose +8 field equals the token.
   The record index n gives the pin button id 10000 + n.
   - If the record's byte at +0x3e is 0 and its int at +0x18 is not -1, that
     int is stored on the screen (+0x350) and FUN_140fcba50 runs first.
   - Kind code 6 (hookup): it searches a second 64-byte array for the hookup's
     index m and activates button 11000 + m, or logs
     "Can't locate hookup index".
   - A missing button logs the "Failed to find required button" message with
     base id 10000 or 11000 and the index.

Conclusions
-----------
Observed:
  - Accessory pins are buttons with ids 10000 + n, one per acc_info_t record,
    keyed by (cart index, slot token). Hookup pins are 11000 + m.
  - Selecting an accessory first switches the tab row (id 499) to the right
    tab, then activates its pin.
Inferred (Hypothesis):
  - Accessories whose slot is one of the 12 run-time tokens (cabin, chassis,
    engine, transmission, paint ...) have no pin; they use the fixed tab
    buttons 500-572.
  - Other accessories live under "e_accessories" (560) unless their slot is an
    interior slot (the token list) or `steering_w`, which go under
    "i_accessories" (570).
  - 571 and 572 are tab ids with no button in this file (trailer or unused).
Unknown:
  - Where the pins are positioned on screen and which code creates the
    acc_info_t records (likely the caller FUN_140fbf860 or the writer of the
    array at screen +0x208).
