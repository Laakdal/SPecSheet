# How each file in research/evidence/ is made again after a game update
# (docs/version-ports.md). `cargo xtask recipes` checks this list without the
# game; `cargo xtask recipes --compare` (ETS2_DIR set) runs it and compares the
# output with research/baseline/; `--save` writes the baselines.
#
# One line per command: <evidence file> <kind> <command or text>
#   game <command>     output depends on the install only; compared with the baseline
#   digest <command>   output is game file content; the baseline keeps only its hash
#   user <command>     reads the user's mod folder or profiles (<home>, ETS2_HOME);
#                      run with --user, never compared
#   rea <file | ->     an executable search batch in research/rea/: its search and
#                      trace seeds find the code again in a new build, its function
#                      and xrefs lines are the old addresses (`cargo xtask rea` prints
#                      the batched commands); - = only results in the evidence file
#   hand <text>        recheck by hand: what to look at
#   historical <text>  cannot be made again: why
# A command is a research example (crates/specsheet-research/examples) and its
# arguments, or `python tools/research/<script>.py ...`. <game> is ETS2_DIR,
# <home> the ETS2 home folder, <scratch> a temporary folder of the run.
# "Double quotes" keep spaces in one argument; `*` in a file name expands to
# the matching files, sorted. A game recipe's output must hold only our
# observations (names, ids, counts, numbers); a tool that prints game file
# text is a digest recipe.
